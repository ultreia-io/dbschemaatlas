# Maintainer development guide

Development follows the same Gitflow model as `dbiutils`: `develop` is the
default integration branch, `main` is production, and releases use
`release/*` or `hotfix/*` branches through the Perform Release workflow.

## Local dependencies

Install `dbiutils` from GitHub without committing a local path:

```r
pak::pak("ultreia-io/dbiutils")
```

For sibling-repository development only, install it explicitly in your local
library before loading this package:

```r
devtools::install("../dbiutils", upgrade = "never")
```

## Validation

```r
devtools::load_all()
devtools::build_readme()
devtools::document()
devtools::test()
devtools::check()
pkgdown::build_site()
```

Tests, README examples, vignettes, and the website use offline fixtures and
must not require database credentials. Coverage is generated by the Test
workflow and uploaded only when `CODECOV_TOKEN` is available.

## Release

Add an exact `# dbschemaatlas x.y.z` NEWS heading, validate locally, then run
the Perform Release workflow from `develop`. The workflow validates one
immutable commit, merges it to `main`, tags it, merges back to `develop`, and
starts archive and website publication. Do not manually create release tags.
